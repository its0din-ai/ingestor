API usage and web features

Authentication

All API endpoints require a bearer token, sent in the Authorization header:

Authorization: Bearer $TOKEN

Upload API

EndpointMethodPurpose
/uploadPOST / PUTUpload a single file
/ (any path)non-GETAccept-and-log sink for any request

Multipart form

curl -H "Authorization: Bearer $TOKEN" -F "file=@myfile.txt" http://host/upload

PUT raw body

curl -H "Authorization: Bearer $TOKEN" -T myfile.txt http://host/upload

POST raw body with filename

curl -H "Authorization: Bearer $TOKEN" --data-binary @myfile.txt "http://host/upload?name=myfile.txt"

The original filename is resolved from the multipart part, a Content-Disposition header, the ?name= query param, or falls back to upload-<unix-timestamp>.

Response

{
  "status": "ok",
  "message": "File received",
  "size": 1048576,
  "quarantined": false,
  "timestamp": "2026-08-20T15:04:05Z"
}

The stored filename is never returned.

Web Features

  • Files — browse, search, download, and delete uploaded files, with per-file status and uploader IP.
  • Settings — hot-reload upload directory, max upload size, bearer token, quarantine extensions, and admin password.
  • Audit — paginated log of every login, upload, settings change, and file action.
  • Dark / light theme — toggled from the sidebar, persisted in your browser.

Security

  • Bearer-token auth with constant-time comparison.
  • Dangerous extensions are quarantined with a .quarantined suffix.
  • Saved files are chmod 0644 — execute bits stripped.
  • Filenames are sanitized against path traversal; uploads stream to disk with a size cap.
  • Admin sessions use a CSRF token plus an HttpOnly, SameSite=Strict cookie.
