API usage and web features

Authentication

API uploads require a bearer token from the Tokens view, sent in the Authorization header:

Authorization: Bearer $TOKEN

The admin console uses a JWT (HS512) session cookie named session. Logging out destroys the token server-side, and changing the admin password signs out every active session. Login is rate limited to 15 attempts per 15 minutes per IP.

Arbitrary upload (token)

curl -H "Authorization: Bearer $TOKEN" -F "file=@myfile.txt" {{.BaseURL}}/upload
curl -H "Authorization: Bearer $TOKEN" -T myfile.txt {{.BaseURL}}/upload
curl -H "Authorization: Bearer $TOKEN" --data-binary @myfile.txt "{{.BaseURL}}/upload?name=myfile.txt"

The original filename is resolved from the multipart part, a Content-Disposition header, the ?name= query param, or falls back to upload-<unix-timestamp>.

Response

{
  "status": "ok",
  "message": "File received",
  "size": 1048576,
  "quarantined": false,
  "timestamp": "2026-08-20T15:04:05Z"
}

The stored filename is never returned. Uploads made with a bearer token are recorded in the audit log with the token's short id (e.g. bearer token id a3f9c2 used for upload: report.pdf).

Web Features

  • Files — browser uploads (drag-and-drop with progress), search, text previews, download, quarantine/release, public sharing, and delete, with per-file status and uploader IP. Shows a live disk-usage monitor (uploads / used / total, % free).
  • Exfil — the same file actions for files uploaded via the API (/upload), kept separate so browser uploads and token uploads are easy to tell apart.
  • Settings — hot-reload upload directory, max upload size, quarantine extensions, and admin password. Changing the admin password logs out all sessions.
  • Tokens — create, copy, and delete bearer upload tokens, each with an optional label and expiry. Omit the expiry for an indefinite token.
  • Audit — paginated log of every login, upload, read, download, quarantine/release, public-share access, settings change, and file action, with client IP and User-Agent, pruned after the configured retention (default 30 days).
  • Dark / light theme and a collapsible sidebar — toggled from the sidebar, persisted in your browser.

Public Sharing

Mark any non-quarantined file as public from the Files view (share button) to make it readable or downloadable without authentication:

{{.BaseURL}}/pub?name={filename}

Text files are served inline as text/plain; everything else downloads as an attachment. Marking a file private (or quarantining/deleting it) revokes the link immediately. Private or quarantined files return 404 from /pub. Every /pub request — successful or denied — is recorded in the audit log with the client IP and User-Agent.

Security

  • Bearer tokens matched with constant-time comparison; each token may carry its own expiry.
  • Admin sessions are HS512-signed JWTs pinned to the HS512 algorithm, with a server-side allowlist so logged-out tokens are rejected even while the signature is valid.
  • Login is rate limited per IP; password changes invalidate all sessions.
  • Dangerous extensions are quarantined with a .quarantined suffix; files can be quarantined or released from the UI.
  • Saved files are chmod 0644 — execute bits stripped.
  • Filenames are sanitized against path traversal; uploads stream to disk with a size cap.
  • CSRF protection via a double-submit cookie, plus HttpOnly, SameSite=Strict session cookies.
  • SQLite runs in WAL mode with a single connection and busy timeout, so concurrent uploads cannot lock the database.
