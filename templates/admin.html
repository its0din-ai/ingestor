API usage and web features

Authentication

API uploads require a bearer token from the Tokens view, sent in the Authorization header:

Authorization: Bearer $TOKEN

The dashboard uses a secure session. Signing out revokes it immediately, and changing a password signs out that account's active sessions. Login is rate limited to 15 attempts per 15 minutes per IP. The superadmin manages accounts from the Users view; regular users only ever see their own storage and activity.

Upload API

Two upload paths exist:

EndpointAuthPurposeStored name
{{.BaseURL}}/uploadBearer tokenArbitrary file upload (script/curl/agents)Original name + random suffix (no collisions)
{{.BaseURL}}/dashboard/uploadSigned-in userBrowser upload from the Files viewOriginal name, kept as-is (refuses duplicates)
{{.BaseURL}}/ (any path)Bearer tokenAccept-and-log sink for any request—

Arbitrary upload (token)

curl -H "Authorization: Bearer $TOKEN" -F "file=@myfile.txt" {{.BaseURL}}/upload
curl -H "Authorization: Bearer $TOKEN" -T myfile.txt {{.BaseURL}}/upload
curl -H "Authorization: Bearer $TOKEN" --data-binary @myfile.txt "{{.BaseURL}}/upload?name=myfile.txt"

The original filename is resolved from the multipart part, a Content-Disposition header, the ?name= query param, or falls back to upload-<unix-timestamp>.

Response

{
  "status": "ok",
  "message": "File received",
  "size": 1048576,
  "quarantined": false,
  "timestamp": "2026-08-20T15:04:05Z"
}

The stored filename is never returned. Uploads made with a bearer token are recorded in the audit log with the token's short id (e.g. bearer token id a3f9c2 used for upload: report.pdf).

Web Features

  • Files — browser uploads (drag-and-drop with progress), search, text previews, download, quarantine/release, public sharing, and delete, with per-file status and uploader IP. Shows a live disk-usage monitor (uploads / used / total, % free).
  • Exfil — the same file actions for files uploaded via the API (/upload), kept separate so browser uploads and token uploads are easy to tell apart.
  • Settings — hot-reload upload directory, max upload size, and quarantine extensions (superadmin), and change your own password. Changing a password logs out that account's sessions.
  • Users — superadmin only: create accounts, set storage quotas, disable or delete users, inspect file metadata, and wipe storage. Passwords are changed by each user from Settings; the superadmin cannot reset them or access user file content. The superadmin only browses the shared workspace.
  • Tokens — regular users get one personal API token, masked by default in the Tokens view. The superadmin manages the workspace's API tokens.
  • Audit — paginated log of every login, upload, read, download, quarantine/release, public-share access, settings change, and file action, with client IP and User-Agent, pruned after the configured retention (default 30 days). Click a remote IP to open its ipinfo.io lookup in a new tab. Actions received through the CF proxy are labeled via cf-proxy in their summary.
  • Dark / light theme and a collapsible sidebar — toggled from the sidebar, persisted in your browser.

Reverse Proxy (nginx / Cloudflare / FlareProx)

ingestor can sit behind any reverse proxy that forwards the original client IP — nginx, Cloudflare, or a FlareProx Cloudflare Worker pass-through. When it does, set trust_proxy_headers=true in .env (and cookie_secure=true if the proxy terminates TLS) so the audit log records the real client IP and generated links use the external scheme/host. The real client IP is resolved in priority order: X-Morph-Real-Ip, then CF-Connecting-IP (Cloudflare), then X-Forwarded-For. Keep the setting off when clients can reach the listener directly, otherwise a client can spoof its logged IP with a forged proxy header.

Public Sharing

Mark any non-quarantined file as public from the Files view (share button) to make it readable or downloadable without authentication:

{{.BaseURL}}/pub?name={filename}

Text files are served inline as text/plain; everything else downloads as an attachment. Marking a file private (or quarantining/deleting it) revokes the link immediately. Private or quarantined files return 404 from /pub. Every /pub request — successful or denied — is recorded in the audit log with the client IP and User-Agent.

Security

  • API tokens are matched securely and may carry their own expiry.
  • Sessions are signed server-side and revoked immediately when you sign out or change your password.
  • Login is rate limited per IP; password changes invalidate all sessions.
  • Dangerous extensions are quarantined with a .quarantined suffix; files can be quarantined or released from the UI.
  • Saved files are stored without execute permissions.
  • Filenames are sanitized against path traversal; uploads stream to disk with a size cap.
  • Forms are protected against cross-site request forgery.
